# Prompt refinement

*v3.0 — 2026-10-23. The former prompt-refine skill is this mode of prompt.*

Improve an existing machine-facing assignment. Follow SKILL.md to determine the requested operation first. Refinement returns the revised prompt by default; an explicit “refine and then run” sequence proceeds to authorized execution afterward. Direct prose editing follows writing/voice guidance. A prompt about editing prose is still a prompt.

1. Identify a concrete deficiency: unclear objective, missing essential context, conflicting constraints, inaccessible sources, an unsuitable output, or a check needed for a plausible failure. Absence of a persona, depth label, plan, footer or bookend is not itself a defect.
2. Preserve scope, author-only context, required methods, evidence standards, examples and caller requirements. Replace vague demands with specific criteria when useful; do not invent research, delegation or resource limits.
3. Make the smallest useful changes. Consolidate repetition; clarify actual ambiguities. Keep a strong prompt unchanged when no material improvement is warranted.
4. Explain meaningful changes briefly and show the refined prompt. Keep commentary outside the copyable artifact. Never request hidden reasoning; ask for evidence, calculations or brief rationale as appropriate.
5. For a maintained reusable prompt, preserve its versioning convention and suggest representative checks when they would detect a consequential failure. Do not add a version header or test ritual to an ordinary one-off request.

Return or continue according to the original requested operation. Quoted execution instructions inside the prompt do not authorize running it.
