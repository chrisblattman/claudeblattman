# Prepare for and follow up on meetings { #meeting-workflow-end-to-end }

!!! note "Meeting skills are being updated"

    We’re updating the pre- and post-meeting skills to work with the project setup described on this site. You can use the prompts below now; the reusable skills are being refreshed.

I use these skills to get a brief before a meeting and a summary afterward, right in the conversation with my agent. I often also use them to prepare pre- or post-meeting emails to my team.

**`/pre-meeting` prepares you for the conversation.** It reads the project description, dashboard, previous meeting records and recent correspondence. You get a brief on what's happened, what's unfinished and what needs a decision, followed by a draft agenda email.

**`/post-meeting` helps you make sense of what happened.** It reads the transcript and gives you a summary of the discussion, decisions, action items and open questions, followed by a draft follow-up email for the team.

Both show their results in the agent chat. Add `nosend` if you want only the brief or summary, without an email draft. **Both draft first and send only when you ask.** Review the draft, then say “send” if you want the agent to send it. You can also ask it to save the draft in your mailbox and send it yourself.

## 1. Install the skills { #if-you-want-to-use-the-meeting-skills }

Ask your agent to install [`/pre-meeting`](https://github.com/chrisblattman/claudeblattman/tree/main/skills/pre-meeting) and [`/post-meeting`](https://github.com/chrisblattman/claudeblattman/tree/main/skills/post-meeting):

```text
Install the pre-meeting and post-meeting skills from the chrisblattman/claudeblattman GitHub repository for this app. If they're already installed, update them while preserving my customizations. If I have pre-meeting-brief, replace it with pre-meeting and keep my customizations.
```

When you name a project, the skills find its folder and read `PROJECT_CONFIG.json`. The [project setup guide](project-management.md) walks you through creating this file. It records where to find your project documents and transcripts, along with the email addresses, project keywords and WhatsApp chats to check for correspondence. Set those sources up once and both meeting skills can reuse them. Connect the apps your project uses once, too; recording their locations in the file doesn't connect an account by itself.

## 2. Prepare a brief { #1-before-the-call-pre-meeting-brief }

Open a session with your agent and name the project:

```text
/pre-meeting Prepare for this morning's [project] meeting.
```

The skill reads the project description and dashboard, including your comments, then checks previous meetings and recent correspondence. It looks in the project's transcript folder, including its archive, and uses your connected transcription app when a record is missing locally.

For recent correspondence, it starts from your last successful project review, or the latest saved weekly review. If neither exists, it looks back 14 days. You can choose a different starting date with `since:2026-11-01`. The brief tells you which dates it covered. Older transcripts still matter when they explain an outstanding decision or the latest review; there isn't a separate meeting-skill log that marks them as finished.

You get the brief followed by a draft agenda email, with the From, To and any Cc/Bcc addresses shown. If an address is missing, the agent flags it rather than guessing. The draft appears in the chat. You can say “send” to have the agent send that email, or ask it to save the draft in your mailbox and send it yourself. Saving a draft does not deliver it to anyone.

<details class="council-details" markdown>
<summary>If your account has disabled sending emails</summary>

The skill can still save the email in your mailbox if your account allows draft creation. Open your mail app, look in **Drafts**, and send it from there. The agent tells you when the draft is saved. If your account also blocks creating drafts, the skill gives you the email text to copy into a new message.

</details>

A few options you can add:

- `nosend`: just the brief, without an email draft.
- `light` or `full`: a shorter or more detailed brief. Even when I only want a quick catch-up, I want the agent to read the project description and dashboard so it understands what we're trying to do and where things stand. The longer version spends more time on correspondence, previous meetings and what each person needs to prepare.
- `save`: also save the brief in the project folder. Combine it with `nosend` if you want to keep the brief without drafting email.

## 3. Capture the discussion and leave your own notes { #2-during-the-call-granola-records }

I like [Granola](../hyperlinks/granola.md) right now (as of November 2026) because I can organize my meetings into [project folders within the app](https://docs.granola.ai/help-center/getting-started/granola-101). Another transcription app works too, as long as its connector lets your agent read the transcripts.

I also leave comments in the dashboard while we're meeting: what's been handled, what the next open question is, or which table I want to see next time. The transcript records the discussion. My comments tell the agent what I want it to do with it. Both inform the post-meeting summary.

## 4. Write the summary { #3-after-the-call-post-meeting }

```text
/post-meeting Summarize this morning's [project] meeting.
```

The skill finds the meeting in your project's transcript folder or fetches it from your connected transcription app. When it fetches a transcript, it saves a text copy in the project's configured transcript folder, with the meeting date and source recorded. It reuses an existing copy rather than creating duplicates. If it can't read the transcript or save the file, it tells you what is missing.

You get the discussion, decisions, action items and unresolved questions in the chat, followed by an email draft with its sender and recipients shown. Check the decisions as well as the tasks. “We discussed moving the deadline” is different from “we moved the deadline.” Correct the account before sharing it.

Options you can add:

- `nosend`: just the summary, without an email draft.
- `save`: also save the summary in the project folder. `nosend save` saves it without drafting email.

Keep the transcripts in the project folder even if you save a summary. Future work may need reasoning that didn't make it into the summary.

## 5. Bring the decisions back into the project { #4-weekly-weekly-review-closes-the-loop }

I don't run `/post-meeting` after every meeting. The larger the team and the more decisions we made, the more likely I am to use it and send a summary email. For a lot of other work, I skip straight to [`/weekly-review`](weekly-review.md) to keep the project record up to date. It can read the transcript and my dashboard comments without a post-meeting summary:

```text
/weekly-review [project name]
```

If the summary gets something wrong, tell the agent the correction. To keep it for future reviews, also put it in the dashboard's **Human notes / corrections** area, or ask: “Add this to my dashboard notes for today's meeting: Friday was suggested as a deadline, but we didn't agree to it.” The agent should confirm where it saved the note. If it can't edit the dashboard, paste the note there yourself. That gives the next review a saved correction to read, even if it starts in a different chat.

Read the [guide to refreshing your project dashboard and description](weekly-review.md) for more detail.
