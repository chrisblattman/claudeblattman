# Broader daily check-in

Use only for `full` or an explicit broader mode. The email-focused default remains in SKILL.md. The same approval, preview, state, and sending rules apply here.

## Modes

- `full`: email review plus configured reminders, calendar/meeting preparation, and priorities.
- `quick`: concise status and priorities, without interactive reminder/email decisions. Normal triage may run unless no-triage or preview was requested. Do not mark unpresented FYIs read.
- `tomorrow`: read-only tomorrow's calendar and preparation needs. No ordinary triage or mail changes.
- `no-email`: broader routine without the interactive email review. Ordinary triage may still run unless explicitly skipped.
- `no-reminders`, `no-prep`, and `no-triage`: skip those respective portions. Do not interpret a temporary skip as permanent configuration.

## Prepare only the requested context

Use available approved connectors, current policies, and saved paths. Calendar, task-app, meeting transcript, and goals connections are optional; report missing context and continue where useful. Do not install private prefetch, AppleScript, or email scripts. Do not assume goals/calendar preferences from another person's setup.

Run the installed canonical triage workflow when applicable, never a copied inline phase with its own state logic. Respect holds and return coverage evidence. Once it completes, fetch independent calendar/reminder context efficiently with the approved tools. Avoid duplicate mailbox writers.

## Review with the user

1. Show a compact time-appropriate status: relevant meetings, urgent tasks, and triage results with their actual coverage. Do not fabricate goal scores or unread totals.
2. Review reminders from the chosen app, separating real deadlines from flexible dates. Collect clear keep/reschedule/done decisions, apply only the requested changes, and verify. A reminder's title is not enough to identify it when duplicates exist.
3. Prepare for a few imminent key meetings using the calendar and available prior discussion. State known commitments and unresolved questions without inventing tasks.
4. Run the normal email review if requested, using its two groups and durable batches. Do not substitute the old summary-only state or bypass send approvals.
5. Suggest the next useful work from the user's actual priorities and remaining time. Save decisions and unresolved work in the existing project/task system, without making a second competing task list.

Preview remains read-only across all portions, including local operational state. A reminder completion, calendar edit, or send needs the user's applicable instruction; merely running a broad check-in is not blanket permission for them.
