For a general run, enumerate the homepage essentials and retain coverage of every directly linked checklist page. Read shared destinations once and cover each relevant section. This coverage can continue alongside an agreed lesson; record pending pages rather than making completion a prerequisite for teaching. When starter practices are established or advanced coverage is appropriate, use the sequence below and read its relevant destinations, including necessary linked skill definitions. Use the site's next-steps index to check source changes, not to override this agreed ordering or restore merged standalone lessons. Account for individual entries rather than stopping at category headings. Add project use, skills experience and automation as described in [assessment and continuity](assessment.md); do not present these additions as separate homepage items.

Use the source page as teaching material through [walkthrough behavior](walkthrough.md), not merely as a link for the user to read. The writing-learning system belongs in starter coverage; repeatable skill maintenance is a separate advanced practice. The sequence below defines the default intermediate/advanced order; the user's priorities, dependencies and established practices can change the next useful lesson.

Assess councils and adversarial review as separate practices even when the homepage groups them or links both to the same page. Read that destination once, then keep distinct evidence and status for development with a council and examination by fresh reviewers. Human judgment and multiple-model experience do not substitute for either check.

For a narrower task, read the relevant page and maintained links only. For either route, read the destination before recommending technical steps. The user already has an agent; do not reinstall it merely to satisfy an introductory checklist item. Checklist coverage does not require crawling unrelated site navigation or all links inside every destination.

For an unavailable page, its public Markdown source is at `https://raw.githubusercontent.com/chrisblattman/claudeblattman/main/docs/` plus the source path above. For downstream pages, resolve the actual source through repository navigation or an edit/source link; do not guess that every URL maps directly to Markdown. The [public repository](https://github.com/chrisblattman/claudeblattman) also provides maintained skill sources. Keep source dates and access limits clear. Record unavailable or not-yet-published guidance while still asking about the associated practice.

## When the site cannot be reached

The following is bundled guidance adapted from the first-session workflow, not a fresh reading of the site:

- Use the coverage prompts in [assessment and continuity](assessment.md) and label them as a dated fallback. Record source gaps rather than claiming live checklist coverage.
- Ask about missing information only when it changes the next action, reusing what the user already established.
- Keep pending coverage explicit and show the checklist snapshot and recommendations visibly. An agreed lesson can proceed from sufficient verified or clearly labelled fallback material while unrelated discovery remains pending. Assessment-only requests end with the report; guided lessons use real work, teach the reusable invocation and revise results with feedback. Completed reports and lessons end without a compulsory question panel.
- Preserve assessment findings in the chosen shared location and link existing project handoffs.

These principles can support useful offline work. They cannot establish current app settings, installation commands, provider availability, prices, or the latest site recommendations. Do not present offline operation as a guarantee that every requested capability works.

## Existing skills own their procedures

The optional starter kit's `kit-hello` checks installation and prerequisites; `kit-setup` handles optional provider connections. Council, adversarial-review, and done own their respective workflows. Use the applicable installed instructions when available. Do not copy their changing scripts, fixed panel sizes, settings, or installers into Blattify. Missing helpers do not prevent ordinary task work.

Public sources are cited for attribution and further reading. Blattify adapts them to the user's task; it does not impersonate Chris or reproduce his private environment.
