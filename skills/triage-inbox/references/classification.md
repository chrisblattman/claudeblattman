# Classification and exceptions

Apply the policy's explicit choices and holds before these guidelines. Missing rules mean keep visible or propose a rule, not invent a destination. All branches require sufficient message content.

## Order of decisions

1. **Protect:** Keep important people, substantive human/project mail, requests, security/payment issues, deadlines, and uncertain cases in the inbox with their current read state. CC and lack of an explicit ask do not remove protection. Existing review labels do not remove it either.
2. **Already handled:** If current labels satisfy the approved action, leave them alone. Do not reclassify existing expense categories. A read message or label does not prove its task is done.
3. **Narrow approved routing:** Apply reviewed content-based exceptions. A completed automated submission acknowledgment differs from a request to submit. A temporary delivery retry differs from permanent failure. Read the actual notice rather than scoring quoted words from the original email.
4. **Expenses:** Match configured vendors and receipt content, then use the agreed category. Billing failures, overdue invoices, disputes, and expiring payment methods need attention. Do not infer business/personal status without an explicit rule.
5. **Travel and invitations:** Approved routine confirmations may be filed. Changes, cancellations, check-in requests, and human messages stay visible. For invitations, inspect title/time/invitation data and query the configured calendar for presence and attendee response. Group duplicates by verified event. If verification fails or response is needed, report it and keep visible unless a rule explicitly permits that case. Do not modify the calendar or RSVP.
6. **Missed filters:** For inbox mail matching an existing documented Gmail filter, apply only its approved action after protections. Current holds and policy override older filter documentation. Do not change the filter.
7. **Routine bulk mail:** Use reviewed sender patterns and content to distinguish reading, school notices, announcements, or automated mail. Respect any user-configured classification thresholds, but only after protections. Bulk headers, formatting, no-reply senders, and generic greetings are supporting evidence only. A university domain is not permission to file research correspondence.
8. **No confident match:** Keep visible and report the uncertainty. Do not invent labels or replace historical FYI with announcements.

## Label-in-inbox sweep

Search inbox messages carrying configured skip-inbox labels within this run's bounds. Fetch content and apply the same protections before removing INBOX. Preserve read state unless a current approved rule explicitly says otherwise. Never sweep family/protected or historical FYI labels merely because they exist. Include sweep candidates in the same overall limit and coverage accounting.

## Interactive matters

Student inquiries, introductions, scheduling choices, and bespoke replies belong in the attention report for the user or `/checkin`. Keep originals visible. Triage never sends or forwards and needs no institutional reply templates. A later reply workflow can use the user's own templates and normal send approvals.

Quarantine digests and recovery notices whose original messages are unavailable need review. Do not import an institution's release/allowlist/forwarding procedure. Keep them visible and identify missing evidence.

## Compact report

- Attention: sender, subject, link, reason, and any hold.
- Filing: exact message IDs, proposed or verified label/archive/read action, and reason. Separate verified changes from attempted/uncertain changes.
- Coverage: actual start/end, completed pages/bodies, excluded or limited work, unresolved operations, and checkpoint advanced or retained.
- Optional: calendar presence/RSVP, filter candidates, and unread inbox count from an actual count source or labeled estimate.

For `/checkin`, return the same evidence instead of starting a second interactive session. Completed triage is not approval to send or clear unresolved obligations.
